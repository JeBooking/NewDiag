# 诊断流程平台

把设备故障的排查经验画成流程图，发布成固定版本，按图执行。平台负责调用业务 Python 接口取数与判断，现场的处置由人完成，全过程留痕。

- **不碰设备**：只读数据接口，动作由人对着设备做
- **发布即冻结**：已经发布、正在使用的版本不受后续编辑影响
- **全程可回查**：每次调用的参数、返回值、走的分支、人工选择和时间都有记录
- **生成代码执行**：每个实例固定一份业务源码，生成独立 Python 程序后在后台运行

设计细节见 [docs/spec.md](docs/spec.md)，协作规则见 [AGENTS.md](AGENTS.md)，**部署到内网服务器上长期运行**看 [docs/deploy.md](docs/deploy.md)。

- [用户手册](docs/user-manual.md)：从示例开始，完成工程登记、槽位配置、发布执行、人工待办与回退。
- [开发者手册](docs/developer-manual.md)：普通 Python 模块接入契约、参数与展示映射、状态保存、生成执行及框架扩展入口。
- 接入速查见[通用工程槽位接入](docs/slot-integration.md)。

示例工程：

- [composed-basic](examples/composed-basic/README.md)：最小可跑示例，两个普通工程。
- [slot-showcase](examples/slot-showcase/README.md)：全功能示例，三个工程、五种展示、现场参数、跳转与并行分支。
- [desktop-mvc](examples/desktop-mvc/README.md)：把一个 Tkinter 桌面应用的 Model 与 View 直接当处理、展示模块接入。
- [code-export-standalone](examples/code-export-standalone/README.md)：无第三方依赖、无资源、无输入，用来查看导出的代码并在本地直接运行。

## 快速开始

### 用源码跑

需要 Node 20.19+、pnpm、Python 3.11+。

首次准备后端：

```bash
cd backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
```

回到仓库根目录，装前端依赖并同时启动前后端：

```bash
pnpm install
pnpm dev
```

前端 http://127.0.0.1:5173，后端 http://127.0.0.1:8000（接口文档 `/docs`）。开发态由启动脚本监控 `backend/app`，源码变化后重启后端；生成代码目录 `data/executions` 不参与监控。

需要盯着应用日志时双击 `start-dev-logs.cmd`：它在启动前后端的同时另开一个窗口跟随 `backend/logs/app.log`。守护进程自己的重启原因写在 `backend/logs/dev-all.log`，后端启动时会把上次没跑完的实例点名记进 `app.log`。

### 用离线包

```bash
backend/.venv/Scripts/python scripts/build_bundle.py
```

产物是 `deploy/newdiag-win64-<日期>.zip`，拷到目标机器解压后：

1. 双击 `setup.cmd`：用本机 Python 建虚拟环境，从 `wheels/` 离线装依赖
2. 双击 `start.cmd`：浏览器打开 http://127.0.0.1:8765/

目标机器需要 **Python 3.11 / 64 位**。内网他机访问用 `start-lan.cmd`。

## 上手五步

### 1. 登记业务工程

进顶部「工程」→「登记工程」，填名称、工程路径、模块名；解释器默认 `python`。

- **名称**是槽位引用的键，登记后不能改；路径、模块、解释器随时可以编辑
- 点「接口」能看到实际探测到的类、方法和函数签名；改完代码点「重新发现」
- 删除工程后，引用它的流程会在下一次探测或发布时报「工程未登记」，重新登记同名工程即可恢复

### 2. 建流程

「流程」页可以新建，也可以导入 `.json` 流程文档或平台导出的 `.zip` 包。运行模式不保存在流程里。

左侧目录树支持多级目录；流程通过列表里的「移动到…」归类。删除目录要求目录为空。

### 3. 设计与发布

画布上拖节点、连线。节点类型：开始、排查、排查动作、结论、处置措施、问题解决、上升、跳转。

- 开始节点是唯一入口，不能删除；启动参数在这里声明
- 开始节点：声明启动参数，填构造槽（一个外接工程一个对象），可选填拉取与处理槽
- 排查节点：固定四个槽——拉取（可选）、处理（可选）、展示（必填，选类型）、判定（必填，可人工判断）
- 槽位参数只有四种来源：固定值、启动输入、现场填写、上一槽结果
- 节点右上角显示校验问题数量；工具栏「自动布局」可以整图重排

「保存」把当前编辑提交为在线版本并释放编辑锁；「发布」才会编译成执行用的步骤表。发布后版本不可修改。

### 4. 启动一次诊断

流程列表点「执行」，或设计页点「开始执行」，按**最新发布版本**启动；版本页里也可以对某个历史版本点「启动执行」。

填写启动参数，选择串行／并行及并行上限，点「开始执行」。缺省串行、上限 4。并行分支在独立进程中运行，人工等待仍占名额；分支结束后调度排队思路。

启动会复制本次业务源码并生成独立 Python 程序；下一次启动使用当前源码，接口不兼容时提示重新调整发布。

### 5. 处理待办

实例详情右侧是待办面板：

- **判断类**：是 / 否
- **参数类**：填写现场参数后提交；业务校验失败保留待办，可修正重试
- **动作类**：完成 / 回退；回退要选一个已完成的具体到访和后继分支，原因可选
- 串行流程找到问题后队列还有剩余时，会多一个「结束排查 / 继续排查」的选择

回退到已完成节点时复用其结果，不重跑目标节点、不重新要求人工输入。已取得的固定数据保留，历史记录不删除。

## 编辑锁

- 进设计页只是只读，不占锁；**第一次改动**才拿编辑锁
- 别人持锁时页面只读，顶部显示谁在编辑
- 保存后锁释放，可以继续改，下次改动再重新拿
- 离开且没保存，草稿和锁都会保留；点「放弃」才丢弃草稿并释放

## 导出与迁移

- 流程列表「导出」导当前在线版本；版本页「导出」导指定的发布版本
- 包内是 `workflow.json`、`attachments/` 和 `manifest.json`；业务工程代码不打包
- 「导入」支持 `.zip`，附件按内容重新入库
- 实例详情的「导出代码」下载该次生成的流程、运行库及业务 Python 源码，附输入配置模板；不包含依赖环境、上传文件或执行现场。它与流程导出是不同的 ZIP，不能作为流程包回导

## 内网其他机器访问

```bash
backend/.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
pnpm dev:lan          # 访问 http://<那台机器的内网IP>:5173
```

浏览器只访问 5173，`/api` 由 Vite 在服务端代理到 8000，不涉及 CORS；需要在服务端防火墙放行 5173。离线包直接双击 `start-lan.cmd`，放行 8765。

这套**没有鉴权**，放行端口等于对内网所有人开放。

## 数据、日志与备份

- 数据：源码方式在 `backend/data/newdiag.db`，离线包在解压目录的 `data/newdiag.db`。SQLite 开了 WAL，备份时停服后复制整个 `data` 目录最稳
- 每个实例的生成代码在 `data/executions/<实例id>/`
- 日志：源码方式在 `backend/logs/app.log`，5 MB 轮转、保留 5 份
- 每个 HTTP 响应都带 `X-Request-ID`

| 环境变量 | 作用 |
|---|---|
| `NEWDIAG_DATA_DIR` | 数据目录，默认 `backend/data` |
| `NEWDIAG_DB` | 直接指定数据库文件或连接串 |
| `NEWDIAG_LOG_LEVEL` | `DEBUG` 打开调试日志 |
| `NEWDIAG_LOG_DIR` | 日志目录，默认 `backend/logs` |
| `NEWDIAG_LOG_PAYLOAD` | 设为 `1` 时把实参与返回值也写进日志 |

## 常见问题

**发布或执行时提示工程未登记、接口不存在**
检查工程路径、模块名、解释器。工程页「接口」能直接看到探测报错。

**执行前被拦住，提示接口签名与发布时不一致**
业务接口的参数改过了。确认改动后再发布一个新版本。

**点了「执行」提示没有版本**
流程还没发布。

**删除工程后流程发布失败**
引用关系还在流程的槽位里。重新登记同名工程，或在槽位里改选接口。

**端口被占用**
源码方式用 8000 和 5173，离线包用 8765。

**别的机器打不开**
确认用的是内网 IP 而不是 `127.0.0.1`，并放行对应端口。
