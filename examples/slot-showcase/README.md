# 槽位方案全功能示例

三个独立团队风格的普通 Python 工程，都不导入平台 SDK。`workflow.json` 把槽位方案的能力全用了一遍，照着改就能配自己的流程。

| 目录 | 角色 | 模块 | 有什么 |
|---|---|---|---|
| `data_source/` | 数据拉取（团队 A） | `feeder` | `DataCenter`：通道目录、按通道取已归档数据 |
| `analytics/` | 处理与展示（团队 B） | `render` | `Processor.smooth`；`Renderer` 出曲线／指标／表格／PNG |
| `judge/` | 判断（团队 C） | `rules` | `Judge`：`check` 返回 `{result, reason}`，`describe` 返回文字 |

## 登记与运行

| 名称 | 目录 | 模块 |
|---|---|---|
| `示例数据源` | 本例 `data_source` 的绝对路径 | `feeder` |
| `示例处理展示` | 本例 `analytics` 的绝对路径 | `render` |
| `示例判断` | 本例 `judge` 的绝对路径 | `rules` |

导入 `workflow.json` → 保存 → 发布 → 执行，启动参数用默认值即可（`threshold` 想走完整链路就改成 `20`，否则振动首个节点就会直接判异常）。

无第三方依赖，PNG 由标准库 `zlib` 手写编码，不需要 matplotlib。

## 覆盖了哪些能力

| 能力 | 在哪 |
|---|---|
| 多个构造槽、同一工程多个对象 | 开始节点：`center`／`processor`／`renderer`／`judge`／`temp_judge` |
| 构造参数来自启动输入、固定值 | `center` 用 `dataset`／`device`；`temp_judge` 固定 `limit=80` |
| 节点各自取数、命中缓存 | 「波形截图归档」「复核判定依据」用与振动检查相同的参数再取，命中缓存 |
| 排查节点拉取 + 处理 + 展示 + 判定 | 「振动曲线检查」：`fetch` → `smooth` → `line` → `check` |
| 表格展示 | 「确认可用通道」 |
| 曲线展示 | 「振动曲线检查」 |
| 图片展示 | 「波形截图归档」 |
| 指标展示 | 「现场指定通道复检」「轴承温度检查」 |
| 文字展示 | 「复核判定依据」 |
| 人工判断 | 「确认可用通道」「波形截图归档」「复核判定依据」 |
| 自动判定 | 振动、复检、温度三个节点 |
| 现场参数 | 「现场指定通道复检」：`channel`、`points` 执行时填 |
| 结论 / 处置 | 三条：通道不完整、振动超限、温度偏高 |
| 跳转节点 | 「转交振动专项」把通道补齐后转回振动链路 |
| 上升与问题解决 | 两条终止路径 |
| 并行分支 | 开始节点同时连出振动与温度两条思路 |
| 数据缓存 | 同一 `fetch` 参数重复到访不再取数（`DataCenter.fetched` 计数可验证） |

## 推荐观察路径

1. 默认阈值执行：先看「确认可用通道」的表格，选「否」继续；振动可能直接判异常，进入处置后点「完成」。
2. 把 `threshold` 改成 `20` 再启动：振动判否 → 看 PNG 波形选「否」→ 现场填 `channel=vibration, points=10` → 看指标卡判否 → 看文字依据选「是」上升。
3. 温度分支会自动跑完；在处置节点确认「完成」后结束。
4. 在人工待办处回退到「振动曲线检查」，改选后继，观察已取数据不重新获取、对象回到那次到访的状态。

## 自己配流程时怎么照抄

- 先想清楚**一台设备上要判断的几件事**，每件事画一个排查节点
- 数据谁用谁取：每个节点在自己的拉取槽里取数，相同参数会命中缓存；开始节点只放"把数据装进对象"的预热
- 展示类型按方法的返回形状选：数组→曲线，`{columns, rows}`→表格，`[{label, value}]`→指标，图片摘要→图片，字符串→文字
- 判定方法只要能返回布尔或 `{result, reason}`，不需要知道平台存在
- 多团队协作时按工程拆构造槽，跨工程只传 JSON
