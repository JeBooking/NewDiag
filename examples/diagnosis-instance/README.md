# 一个流程类、一次诊断对象

本例不需要数据服务器和额外依赖。类在 [diagnosis.py](diagnosis.py)，三份 workflow 可直接导入。
没有数据准备节点，也不在排查节点重复配置获取、解析、展示、判断四阶段。

## 登记、导入、启动

1. 在「工程」登记名称 `诊断实例示例`，路径为本目录的绝对路径，模块 `diagnosis`，工厂留空。
   Python 使用平台后端解释器，或安装了业务依赖的解释器；SDK 由平台提供。
2. 导入 [workflow.json](workflow.json)。点击画布空白处，在「流程属性 → 诊断实例」查看
   `MotorDiagnosis`、版本 `1.0.0` 和阈值配置。开始节点已声明 device_id、time_point。
3. 选择排查节点，可看到它绑定的实例方法，不显示旧四阶段配置。也可自行新建流程：先选诊断类，
   再在开始节点配置 initialize 所需的输入，在各排查节点选择方法。
4. 保存、发布、执行。默认设备 `motor-01`，时间 `2026-11-05T08:00:00+08:00`。

## 主流程发生什么

| 步骤 | 行为 |
|---|---|
| 启动 | 创建 MotorDiagnosis；initialize 获取、解析报告，放入 self.data['report'] |
| 电压排查 | check_voltage 直接使用启动报告，不再次取数 |
| 人工动作 | 保存当前数据版本，释放对象及业务进程；点击「完成」继续 |
| 波形排查 | 重建轻量对象并恢复数据；第一次调用 waveform 才读取、解析波形 |
| 人工判断 | review_waveform 的相同请求命中缓存；展示波形，保存数据版本后释放对象 |
| 人工提交 | 填写依据并选「是／否」；仅接收判断，不重跑方法 |
| 等待后排查 | confirm_waveform 重建对象后继续命中持久缓存，不重取、不重解析 |

把设备改成 `motor-02` 再启动：电压 225V 沿「否」结束，整次诊断不会加载波形。
每次诊断互相隔离；另开实例会重新初始化，不复用上一实例的数据。

## 同级分支与请求区分

- [workflow-parallel.json](workflow-parallel.json)：两个同级排查共享同一波形请求，只加载一次。
  可以把流程模式改成串行，复用语义相同。平台目前逐个调用同实例的节点方法；资源自身仍合并并发请求。
- [workflow-requests.json](workflow-requests.json)：第一个节点用通道 A、scale=1，第二个节点用通道 B、scale=2；
  两个请求分别获取、解析，不会仅因方法名相同而误用缓存。
- 资源键包含诊断类、版本、配置、启动输入、资源名、资源版本及全部有效调用参数（含默认值）。
  位置参数和等价关键字参数会归一成同一请求。变动文件应把文件哈希传给资源方法；查询时间和解析参数同样显式传入。
- None、空列表等正常空结果可缓存；本例把“没有波形”作为排查错误，不能据此返回“否”。
  获取或解析抛异常不写成功缓存，再次请求可重试。

## 日志与回退观察

后端日志中搜索「启动获取报告」「启动解析报告」「首次获取波形」「首次解析波形」及「诊断资源缓存命中」。
对象构造、释放日志带 pid，可核对等待前后进程变化。业务日志通过会话 stderr 转发，观察完整业务日志时
设置 `NEWDIAG_LOG_LEVEL=DEBUG`；SDK 的会话调用记录和实例状态也会写入平台日志。

在等待后查看实例运行记录：开始节点记录初始化；各方法的依据保留具体诊断数据版本引用。
回退到已经加载波形的那次排查并重执行，沿用该次到访的数据，不重新加载；
回退到尚未加载波形的到访，其版本视图里还没有波形，随后首次访问才加载。
较晚加载的其他通道不会混入较早到访的数据视图。处置本身不会清除缓存；
确需新一次测量时，由业务方法显式传入新的查询时间／请求参数，本例不增加刷新按钮。

## 写自己的业务类

- 继承 `diagnosis_sdk.Diagnosis`。__init__ 只建立轻量环境，不进行采集解析；initialize 只在首次启动调用。
- 持久业务数据统一放 self.data；只允许 initialize 写入，读取返回隔离副本。
  大结果只需部分字段时使用 `self.data.field('report', '字段路径')`。
- 给按需获取并解析的方法加 `@resource(version='1')`，正常调用 `self.waveform(...)` 即可命中 self.cache。
  不必逐字段登记，也不必编写缓存键或序列化整个 __dict__。
- 排查方法返回 `{presentation: {blocks: [...]}, result: 'yes'|'no', reason: '依据'}`。
  省略 result 或设为 None 表示人工判断；可选 data 保存该节点的额外结果，平台以产物引用记录。
- 所有保存的数据必须可 JSON 表达，不用 repr 冒充数据。自定义业务对象需在业务边界显式转换成可恢复的数据。
- 连接、客户端、锁等运行资源由 __init__ 或使用处重建，在 close 释放；不把它们放入 self.data。
  普通 self 成员不自动持久化，配置从构造器恢复，业务结果放进受管理数据。
- shared data 与 resource 返回副本，节点不能通过原地修改影响其他节点；衍生结果通过返回值提供。
- 签名、诊断类版本和资源版本随发布冻结；改变算法或数据格式时更新版本并重新发布。

数据产物随 backend/data 备份，暂不自动回收。缺失、损坏或版本不符时报错，不偷偷重新采集。
人工等待恢复不等于平台重启自动续跑；超时／崩溃的重试仍可能重复调用业务接口，获取必须只读、可重复。
