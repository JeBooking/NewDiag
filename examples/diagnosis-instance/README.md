# 一个流程类、一次诊断对象

本例无需数据服务器和额外依赖，类在 [diagnosis.py](diagnosis.py)。
三份 workflow 使用旧文档格式，导入后保存为分层格式；运行模式在启动时选择。

## 登记、导入、启动

1. 登记工程名称 `诊断实例示例`，路径为本目录绝对路径，模块 `diagnosis`，工厂留空。
2. 导入 [workflow.json](workflow.json)，查看流程属性中的 MotorDiagnosis 和各节点方法绑定。
3. 保存并发布。默认设备 motor-01、时间 2026-11-05T08:00:00+08:00。
4. 启动时选择串行或并行；并行上限默认 4，人工等待占一个分支名额。

## 运行行为

| 步骤 | 行为 |
|---|---|
| 启动 | initialize 获取、解析报告，放入 self.dataset = Data(report=selected) |
| 电压排查 | 只读 dataset.report，不重复获取 |
| 人工动作 | 进程及对象保持存活，点击完成后继续 |
| 波形排查 | 首次调用 waveform 获取并解析，后续同请求命中缓存 |
| 人工判断 | 保留展示并等待回复，不重新调用已完成的方法 |
| 等待后排查 | 继续使用固定数据和缓存，日志中的 pid 不变 |

改成 motor-02 会沿电压正常分支结束，不加载波形。另开实例重新初始化。

## 串行、并行与回退

- [workflow-parallel.json](workflow-parallel.json) 含同级分支。串行时共享已取得的数据；并行时真实分进程，分叉后的资源获取各自独立。
- [workflow-requests.json](workflow-requests.json) 的通道 A/倍率 1 与通道 B/倍率 2 是不同请求，各自缓存。
- 并行分叉时原进程继续第一个子分支，其余排队；上限满后等待已有分支结束。没有后继只结束当前路径，不重新跳到同级分支。
- 回退选择已完成到访 B 和新后继，复用 B 输出，不重跑 B、不重新填写 B 的人工数据。
- 固定数据保留该独立分支已取得的内容；后续节点输出不进入新路径，旧运行记录仍可查看。

## 模块数据约定

`Data` 的成员只能填充一次，之后只读。字典、列表、集合转成只读形式；自定义对象由模块保证不可变。
另一种形态放另一成员；节点执行记录通过返回值提供，不用 checked_nodes 这类可变成员传递。
序列化只保存新增 Data 成员，之后引用同一产物；大数据不要在普通成员中另存一份。

`@resource` 保留既有缓存协议，缓存键包含类、配置、输入、资源版本和有效参数；读取返回副本。
None、空列表可缓存，加载异常不写成功缓存。本例将不存在的波形作为错误，不当作正常判断。

启动时固定当前模块源码；正在执行的实例不随工程源码更新而改变。依赖解释器和包仍由部署方维护。
数据目录需整体备份，不只备份数据库。本轮不提供平台重启后的自动续跑。
详细协议见 [诊断类开发手册](../../docs/diagnosis-development-guide.md)。
