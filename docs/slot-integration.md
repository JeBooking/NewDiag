# 通用 Python 工程槽位接入

平台把每个节点摊成固定几个空格，编排者在空格里选外接工程的公开方法；平台生成 Python 代码在后端执行。模块维护者只写普通代码，不登录平台、不继承基类。

本页为接入速查。完整操作见[用户手册](user-manual.md)，模块协议、状态保存和平台扩展见[开发者手册](developer-manual.md)。

## 接入步骤

1. 工程页登记原工程目录、默认模块、解释器，并装好原工程依赖。工程名登记后不可改，它是槽位的引用键。
2. 新建流程，画开始、排查、结论、处置与终止节点；排查节点用是／否两条出线。
3. 开始节点声明启动参数（数组、数字、文件等），再填构造槽：一个外接工程一个对象，参数来自启动输入或固定值。
4. 开始节点可选填拉取槽与处理槽：把数据装进对象（由方法自己保存），返回值不往后传。
5. 排查节点填四个槽，顺序固定：拉取（可选）→ 处理（可选）→ 展示（必填）→ 判定（必填）。展示要选类型（图片／曲线／指标／表格／文字），判定可以选方法或「人工判断」。
6. 参数只有四种来源：固定值、启动输入、现场填写、上一槽结果。接口必填参数必须给来源，否则发布被拦。
7. 保存、发布；发布时逐个探测槽位引用的接口并冻结签名。执行页选串行或并行后再启动。

## 数据怎么走

- 槽位链只在节点内传递：拉取 → 处理 → 展示／判定，用「上一槽结果」接上一步
- 跨节点不传值：下一个节点要数据就自己取（命中缓存），或从对象、数据中心里拿
- 拉取结果按「对象 + 接口 + 参数」缓存，同一次诊断只取一次；回退不重取。拉取槽取消「使用缓存」可跳过缓存
- 跨工程只传 JSON 和文件；业务对象只在所属工程进程里有效

## 对象与状态

会改变状态的对象放构造槽，平台按 pickle 保存对象图。锁、连接、窗口、文件句柄不属于可恢复数据，调用中临时打开并及时关闭更容易接入。人工等待期间进程存活，回退时对象回到目标到访的快照。

## 最小示例与验收

[composed-basic](../examples/composed-basic/README.md) 有两个独立普通工程，业务代码完全不依赖平台 SDK；`workflow.json` 覆盖自动判定、人工判断和现场参数三种节点。

建议手工核对：从零填槽位、保存再打开、发布启动、现场参数与人工判断、在待办处回退、并行数量上限、错误接口定位、重新发布后源码更新。
