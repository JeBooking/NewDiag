# 用户手册

适用版本：设计协议 v1.15，默认使用“组合现有工程”及生成 Python 执行。面向流程编排者和现场排查人员；无需编写诊断基类。部署由管理员按[部署手册](deploy.md)完成，模块开发见[开发者手册](developer-manual.md)。

## 1. 先分清四类内容

| 内容 | 配置位置 | 示例 |
|---|---|---|
| 诊断流程 | 画布上的节点和连线 | 检查电压，异常后检查线路 |
| 模块接入 | 流程属性、节点属性 | 哪个工程的方法负责取数，结果怎样展示 |
| 本次输入 | 启动表单、节点待办 | 文件、阈值、现场提供的数据 |
| 本次运行方式 | 启动执行页面 | 串行／并行、并行数量上限 |

串并行和并行上限不属于流程设计，不随流程保存。发布版本保存当时的编排和接入配置；每次启动会使用登记工程当时的源码，并为该次执行保留源码副本。

## 2. 先跑通现成示例

示例位于仓库 [examples/composed-basic](../examples/composed-basic/README.md)。包含两个普通 Python 工程，不依赖平台 SDK，也没有第三方依赖。

### 2.1 登记两个工程

在顶部“工程”页面选择“登记工程”。下表的目录均填**后端所在机器上**的绝对路径；浏览器所在机器的路径不一定能被后端读取。

| 字段 | 数据工程 | 判断工程 |
|---|---|---|
| 名称 | `组合数据示例` | `组合判断示例` |
| 工程路径 | `<仓库>/examples/composed-basic/data_tools` | `<仓库>/examples/composed-basic/analysis_tools` |
| 模块 | `records` | `checks` |
| 工厂 | 留空 | 留空 |
| 解释器 | 能运行示例的 Python 可执行文件路径 | 同左 |

名称是流程引用键，导入示例时必须与表中一致。路径与解释器需换成实际值。这里的“工厂留空”指工程登记表；需要构造对象时，在组合配置中选择构造器或工厂函数。

### 2.2 导入、发布、执行

1. 进入“流程”页，导入 [workflow.json](../examples/composed-basic/workflow.json)。
2. 打开设计页，在流程属性查看“组合现有工程”。配置已包含 `rules` 实例对象、`dataset` 固定资源和两个排查操作。
3. 保存并发布。若发布失败，先处理校验提示，不必修改原 Python 示例。
4. 开始执行，保留 `samples = [1,2,8,3]`、`limit = 5`，选择串行。
5. “首次检查”应展示曲线，自动判断为“是”，依据中峰值为 8、阈值为 5。
6. 遇到“请现场确认设备状态，完成后继续”时，提交完成。
7. 后续人工判断节点显示曲线，按现场判断选择是或否；示例的两个出口都通向下一个节点。
8. “现场填写倍率后检查”填写数字 `1`，提交后继续自动检查，最终进入结束节点。

以上描述的是示例预期行为，便于核对；不是已完成浏览器验收的声明。

### 2.3 另外两份示例

| 流程文件 | 用途 | 与默认示例的差别 |
|---|---|---|
| [workflow-lazy.json](../examples/composed-basic/workflow-lazy.json) | 按需取数 | 到首次使用 `dataset` 时才加载，后续复用 |
| [workflow-upload.json](../examples/composed-basic/workflow-upload.json) | 上传文件解析 | 启动时上传 [samples.json](../examples/composed-basic/samples.json)，原方法接收本地文件路径 |

三份示例的主链都是顺序依赖，不用于演示真实并行。需要观察并行时，在同一出口配置多个同级排查分支，并在启动时选择并行。

## 3. 从零配置自己的流程

### 3.1 建立流程骨架

新建流程后，在画布添加开始、排查、排查动作以及所需的结论、处置措施、问题解决或上升节点。开始节点为唯一入口；按节点提供的出口连线，排查节点使用是／否分支。

开始节点声明本流程的全局启动参数。例如 `samples` 为数组、`limit` 为数字。后面选择“启动输入”时填写这里的名称。节点上的校验提示可用于定位缺失连线或无效绑定。

流程属性选择“组合现有工程”。从旧接入方式切换时，会清理不兼容的节点绑定；切换后需要重新配置节点操作，误操作可在编辑器中撤销。

### 3.2 配置实例对象

“实例对象”用于需要反复调用的普通业务对象。对象首次使用时创建。

以示例 `rules` 为例：

1. 添加实例对象，结果名称填 `rules`。
2. 选择工程 `组合判断示例`、模块 `checks`，点击“读取接口”。
3. 选择“函数／构造器”，接口选 `create_rules`。
4. 配置参数 `limit`，来源选“启动输入”，名称填 `limit`。

也可以使用构造器，或使用已有对象的方法返回新对象。未勾选配置的可选参数由原 Python 方法使用自己的默认值；必填参数必须配置来源。

### 3.3 配置固定资源

固定资源用于已获取、后续只读取的数据，例如解析后的完整采样数据。它可以是普通对象，也可以是数组、字典等结构化数据。

示例 `dataset` 的配置：

1. 添加固定资源，名称填 `dataset`，加载时机选“诊断启动时”。
2. 添加调用 `loaded`，工程选 `组合数据示例`，接口选 `Dataset`。
3. `values` 参数来自启动输入 `samples`，返回结果选“保留业务对象”。
4. 资源结果选择“此前调用结果”，名称为 `loaded`，字段路径留空。

同一资源及相同请求参数会命中缓存。需要不同数据时，使用不同资源或明确的请求参数。资源名称不代表多个并行进程共用同一块内存：各独立分支持有自己的对象与缓存。

固定资源一旦产生就应只读。解析成新格式时创建新结果，不要让后续方法修改原资源。会改变状态的对象应放在“实例对象”中。

### 3.4 配置排查操作

操作是一组有顺序的接口调用，可以被多个排查节点复用。

示例操作 `inspect` 声明参数 `scale`，依次配置：

| 调用 | 工程和接口 | 目标 | 参数 | 返回类型 |
|---|---|---|---|---|
| `curve` | 数据工程 `Dataset.series` | 固定资源 `dataset` | `scale` 来自操作参数 `scale` | 结构化数据 |
| `verdict` | 判断工程 `ThresholdRules.evaluate` | 实例对象 `rules` | `samples` 来自此前调用 `curve` | 保留业务对象 |

两次调用都选“已有对象的方法”。同一调用列表只能引用此前已经完成的调用；不能引用尚未执行的后续调用。

随后配置展示：折线使用 `curve`；文字使用 `verdict`，字段路径为 `explanation`。开启自动判断，结果取 `verdict.exceeded`，依据取 `verdict.explanation`。字段路径栏只填 `exceeded` 或 `explanation`，因为结果名称已经选了 `verdict`。

不开启自动判断时，平台先完成取数和展示，再生成判断待办；人工提交不会重新执行这些调用。

### 3.5 参数来源怎么选

| 来源 | 使用方法 |
|---|---|
| 固定值 | 填合法 JSON，如 `1`、`true`、`"电压"`、`[1,2]`；文本要带双引号 |
| 启动输入 | 填开始节点声明的全局参数名 |
| 操作／资源参数 | 填操作参数名或本次资源请求参数名 |
| 此前调用结果 | 填同一调用列表中的结果名称 |
| 上游节点结果 | 填节点 ID；字段路径从该节点的输出开始，例如 `data.curve` |
| 实例对象 | 选择命名对象；传整个对象时字段路径留空 |
| 共享资源 | 参数来源菜单中的名称，对应流程属性里的“固定资源”；可附带请求参数 |
| 本次输出目录／图片输出路径 | 传给需要输出位置的原业务方法 |
| 组合列表／组合字段 | 每个元素或字段单独选择来源，组合成列表或字典 |

字段路径用点分隔，例如 `summary.peak`、`samples.0`。不能填写 Python 表达式或方法调用。对象的公开属性在所属工程中读取；整个业务对象不能传给另一工程，跨工程应传数据或文件。

### 3.6 把操作绑定到节点

选中排查节点，选择操作 `inspect`。将 `scale` 配置为固定值 `1`，即可自动获取这个参数。勾选“现场填写”并选择数字类型，则执行到该节点时等待人工输入。

支持文本、数字、布尔、日期时间、文件、数组、对象、JSON 八种输入类型。数组和对象要填结构化内容；例如数组填 `[1,2,3]`，不要填成带引号的字符串。

启动上传文件传给原方法时，勾选“将上传文件引用转为本地文件路径”。现场文件类型输入已经转换为路径。所有路径都是后端可读取的位置。

## 4. 保存、发布和版本

保存用于保留在线流程；发布后才可启动执行。流程列表通常启动最新发布版本，历史版本页可以选择指定版本执行。

发布版本的编排不会随草稿修改。外接工程源码不包含在流程包中：新的执行使用当前登记工程，已启动执行继续使用自己的源码副本。原接口参数变更导致配置不匹配时，需要调整接入配置并重新发布。

首次编辑取得编辑锁，别人持锁时页面只读。保存释放锁；未保存离开可能保留草稿和锁，明确放弃编辑时使用“放弃”。

## 5. 执行、等待和回退

### 串行和并行

启动时选择模式和并行上限，默认串行、上限 4。串行模式按规则依次尝试同级思路；当前路径没有目标后继时，继续尝试排队的同级分支。并行模式已同时开展同级思路，因此无目标后继的路径结束为失败，不再跳去执行另一同级分支。

上限约束独立排查分支的执行名额，不是所有 Python 子进程的总数。达到上限时新分支排队，已有分支结束后释放名额。人工等待期间分支进程存活且占名额；嵌套分支可由当前进程继续其中一条，其他分支按额度调度。

### 处理待办

根据待办类型填写数据、做是／否判断或确认现场动作。人工等待可以持续，不需要重新启动流程。浏览器关闭不等于终止后端执行；可重新打开执行记录查看，但不要停止承载该实例的后端。

### 回退

在界面提供回退入口时，选择一个已经完成的到访及其后继分支，必要时填写原因。当前不提供对任意正在计算的代码行进行暂停和回退。

例如已经从 B 走到 C，在允许回退的待办处回到 B：直接复用 B 的输出，重新选择后继；不会重跑 B，也不会重新索取 B 已提交的人工数据。普通可变对象恢复到 B 的状态，当前独立分支已经取得的固定资源继续保留。B 之后的结果退出新路径，但仍可在历史中查看。

需要完全新的输入或新的数据采集时，启动新的诊断实例。人工等待与平台停机是两回事；当前不承诺后端重启后自动恢复正在运行的诊断。

## 6. 展示和历史

执行详情展示有效路径、节点结果、待办与历史记录。文字、曲线、指标、表格和图片由操作的展示映射决定。查看某次到访时，应同时关注节点、分支及到访时间，不能只凭节点名称区分回退前后的结果。

若当前排查已无继续价值，使用实例的终止操作；终止后保留记录，不等同于删除流程。

## 7. 导入、迁移和排错

流程可导入 JSON 或平台导出的 ZIP。ZIP 包含流程、附件和依赖清单，不包含原业务工程代码、Python 环境或正在运行的诊断进程。迁移时需在目标后端准备工程，并按相同引用名称登记。

| 现象 | 先检查什么 |
|---|---|
| 找不到工程／接口 | 工程名、服务器路径、模块、解释器；在组合调用处“读取接口” |
| 工程页能探测，组合列表找不到类 | 在组合配置中读取普通接口目录；旧协议接口列表不等同于组合目录 |
| 发布提示缺少参数或来源不存在 | 原接口必填参数、开始节点全局参数、操作参数名称、调用顺序 |
| 启动探针没有可解析结果 | 记录完整错误、工程名和解释器，交给开发者检查导入及探针日志 |
| 无法保存对象 | 可能持有连接、锁或文件句柄；请模块开发者调整可恢复对象边界 |
| 提示对象不能跨工程 | 改为公开字段或方法返回的数据，再传给下个工程 |
| 表格／图片显示失败 | 检查展示类型与输出形状；图片应是图片输出，不是普通网页地址 |
| 并行分支一直等待 | 查看名额是否被其他分支或人工待办占用 |
| 前端访问不到后端 | 检查后端日志和启动器状态；不要靠反复提交待办解决服务中断 |

反馈问题时提供流程版本、实例 ID、节点／到访、操作步骤和完整错误。日志和服务启动方式见 [README](../README.md)；不要仅提供截断的“接口探测失败”一句话。
