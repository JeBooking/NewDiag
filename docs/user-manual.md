# 用户手册

适用版本：v1.17，节点槽位模板 + 生成 Python 执行。面向流程编排者和现场排查人员；不需要写平台基类，也不需要把业务逻辑搬进平台。

Windows 源码环境装好依赖后，双击仓库根目录的 [start-dev.cmd](../start-dev.cmd) 即可启动前后端并打开浏览器。保留启动窗口，按 Ctrl+C 停止。

## 1. 平台只做四件事

| 平台做 | 平台不做 |
|---|---|
| 实例化外接工程的对象 | 不描述业务逻辑：解析、计算、画图、判定都在外接工程里 |
| 按图顺序调用槽位里的方法 | 不维护数据对象：数据在对象里或数据中心里 |
| 缓存取过的数据 | 不跨工程搬业务对象：跨进程只传 JSON 和文件 |
| 保存对象状态、留痕、人工等待 | 不替你决定该取什么数据 |

所以配置只有两件事：**开始节点填工程对象，排查节点填方法**。

## 2. 先跑通示例

示例在 [examples/composed-basic](../examples/composed-basic/README.md)，两个普通 Python 工程，不依赖平台 SDK，也没有第三方依赖。

### 2.1 登记两个工程

顶部「工程」→「登记工程」。路径填**后端所在机器**上的绝对路径，浏览器所在机器的路径不一定读得到。

| 字段 | 数据工程 | 判断工程 |
|---|---|---|
| 名称 | `组合数据示例` | `组合判断示例` |
| 工程路径 | `<仓库>/examples/composed-basic/data_tools` | `<仓库>/examples/composed-basic/analysis_tools` |
| 模块 | `records` | `checks` |
| 解释器 | 能运行示例的 Python 路径 | 同左 |

名称是流程里的引用键，导入示例时必须一致。

### 2.2 导入、发布、执行

1. 「流程」页导入 [workflow.json](../examples/composed-basic/workflow.json)。
2. 打开设计页，点开始节点：两个构造槽（`dataset`、`rules`）已经填好。
3. 点「看曲线并判定峰值」：拉取、展示、判定三个槽已填好，展示类型是曲线。
4. 保存并发布。校验不过先看节点右上角的角标。
5. 执行，保留 `samples = [1,2,8,3]`、`limit = 5`，串行。
6. 第一个节点自动判定为「是」，随后停在「人工看曲线判断」的待办：看待办里的曲线选是或否。
7. 下一个节点要求现场填写 `scale`，填 `1` 提交，自动判定后进入结束节点。

想一次看全所有能力（三种展示、现场参数、跳转、并行分支），用 [slot-showcase](../examples/slot-showcase/README.md)：三个团队的工程各一个，照着改就能配自己的流程。

## 3. 从零配置自己的流程

### 3.1 画骨架

新建流程后添加开始、排查、结论、处置措施、问题解决或上升。开始节点唯一且不能删除；排查节点用是／否两条出线。

### 3.2 开始节点：启动参数 + 构造槽

- **启动参数**：本流程的全局输入，发布时冻结成执行页表单。例如 `samples` 选数组、`limit` 选数字。
- **构造槽**：一个外接工程一个对象。填对象名、工程、模块、接口，参数用启动输入或固定值。

```text
对象名 presenter  ← 展示模块 / presenter / Presenter(device=启动输入 device)
对象名 judge      ← 判断模块 / judge / Judge(limit=固定值 5)
```

对象在流程开始时构造一次，后面按对象名引用。纯函数工程可以不填构造槽，槽位直接选模块级函数。

- **拉取槽**（可选）：开始时就取一次数，例如 `client.fetch(metric=固定值 "vibration")`。
- **处理槽**（可选）：对拉取结果做解析，输入用「上一槽结果」。
- 开始节点的取数用于“把数据装进对象”，返回值不往后传；后面节点要用就自己取，或直接读对象。

### 3.3 排查节点：四个槽

固定链：**拉取 → 处理 → 展示 → 判定**，顺序不能改。

| 槽 | 必填 | 填什么 |
|---|---|---|
| 拉取 | 否 | 去取一次数据；结果按「对象 + 接口 + 参数」缓存，同一次诊断只取一次。数据会变时可取消「使用缓存」 |
| 处理 | 否 | 加工本节点拉取的结果；参数用「上一槽结果」接收 |
| 展示 | 是 | 画图或出表，并选展示类型：图片／曲线／指标／表格／文字 |
| 判定 | 是 | 判定方法，或选「人工判断」由人看展示后选是／否 |

展示与判定用「上一槽结果」时，本节点必须先有拉取或处理；不填拉取和处理时，方法自己用对象里的数据（对象在开始节点已经构造好）。跨节点不传值：需要另一份数据就在那个节点自己取。

**判定方法返回什么**：布尔值、`yes`／`no`，或 `{"result": true, "reason": "峰值 9 超过阈值 5"}`。依据会写进执行轨迹。

**展示方法返回什么**：图片返回附件摘要（用 `node_sdk.save_file` 存 bytes，或直接返回 bytes；返回摘要列表则一次展示多张），曲线返回数值数组，指标返回 `{label, value, unit?}` 列表，表格返回 `{columns, rows}`，文字返回字符串。

### 3.4 现场参数

某个槽的参数要等执行到节点才知道（量程、通道号、倍率），在该方法参数上选「现场填写」，平台自动登记成节点的现场参数：执行到这里先弹待办，填完再继续。业务校验失败保留同一待办，可改完重试。

## 4. 参数来源只有四种

| 来源 | 填法 |
|---|---|
| 固定值 | 合法 JSON：`1`、`true`、`"电压"`、`[1,2]`，文本要带双引号 |
| 启动输入 | 开始节点声明的参数名 |
| 现场填写 | 执行到节点时人工填 |
| 上一槽结果 | 本节点拉取或处理的返回值，直接作为参数传入 |
| 展示结果 | 展示槽这次调用的返回值，只有判定槽能选 |

上传的文件参数默认换成本地绝对路径传给方法；确实需要原始引用（`{ hash, name }`）时，在参数上勾「传上传引用而不是路径」。

列表和字典可以逐项组合。不能写 Python 表达式，也不能引用别的节点的输出。

## 5. 保存、发布和版本

保存只写在线版本；发布才编译成执行用的步骤表，并冻结启动表单与接口签名。

- 首次编辑才拿编辑锁，别人持锁时页面只读
- 发布前会逐个探测槽位引用的接口，探测失败或参数不全直接拦下
- 发布不打包源码：每次启动复制当前工程源码，之后改原工程只影响新实例
- 接口参数改了会导致发布版本对不上，需要重新发布

## 6. 执行、待办和回退

### 串行与并行

启动时选模式和并行上限，默认串行、上限 4。串行按深度优先一条思路一条思路走，成功但还有排队思路时会问「结束／继续」；并行每个分支独立进程，达到上限的新分支排队。

数据来自数据中心时取数没有副作用，并行不需要额外加锁。

### 待办

- **判断类**：是／否，必须填写判断依据（人工判断和「判定方法没给结论」两种都算）
- **参数类**：填现场参数
- **动作类**：完成；做不成走回退
- **报错类**：节点执行报错时停下，选「回退到某个节点」继续排查，或「结束流程」；串行结束整个诊断，并行只结束出错这条思路

人工等待期间进程存活，浏览器关掉不影响后端执行。

### 回退

在提供的入口里选一个已完成的到访及其后继分支：复用该到访的结果，不重跑目标节点，不重新要人工输入；对象恢复到那次到访的快照，已经取到的数据继续保留。

## 7. 展示和历史

实例详情底部有两个页签：

- **执行轨迹**：按诊断顺序串起节点动作与人工决定，带时间、结果与依据；回退、排查失败、执行报错都在这里留痕
- **诊断路径**：只看排查思路上的节点。串行只保留当前正在排查的那条，换过思路时给一句说明；并行每条思路单独一行，失败的标「排查失败」并保留

文字、曲线、指标、表格、图片由展示槽的类型决定。区分回退前后的结果要看「节点 + 分支 + 到访时间」，不能只看节点名。

## 8. 导入、迁移和排错

流程可导入 JSON 或平台导出的 ZIP。ZIP 含流程、附件和依赖清单，**不含业务工程代码**；换机器要重新登记同名工程。

实例详情「导出代码」下载该实例启动时固定的代码：流程 Python、运行库、业务源码、配置模板。解压后按 README 准备依赖、填好输入，`python flow.py --mode serial` 就能本地跑，人工输入走终端。

| 现象 | 先查什么 |
|---|---|
| 找不到工程／接口 | 工程名、服务器路径、模块、解释器；在槽位里重新点「读取接口」 |
| 展示槽选不到方法 | 展示类型与返回形状不匹配；实例方法要先选目标对象 |
| 发布提示缺必填参数 | 接口签名里的必填参数没有配来源 |
| 启动探针报错 | 看完整错误和工程名，交给模块维护者检查导入期副作用 |
| 对象不能保存 | 对象持有连接、锁、文件句柄，让模块维护者把运行资源移出可恢复对象 |
| 曲线／图片显示失败 | 返回形状与展示类型不符；图片应是附件摘要 |
| 节点显示「执行报错」 | 接口抛异常，到待办里选回退或结束；「排查失败」则是分支没后继，属于思路不成立 |

反馈问题时给出流程版本、实例 ID、节点与到访、操作步骤和完整错误。
