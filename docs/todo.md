**诉求**：把「程序执行错误」和「诊断没找到原因」分开。

**核实结论**：状态层其实已分开——没找到原因走 escalation 节点、落到 `escalated`；只有业务函数抛异常才落到 `failed`（`scheduler.py:1049` 的 `_refresh`）。真正混在一起的是 `failed` 这个桶，里面装了四类原因：

| error 前缀 | 含义 |
|---|---|
| `execution/*` | 业务函数真的报错 |
| `route/*` | 流程走不下去（返回值判不了是/否、分支没有后继） |
| `plan/*` | 计划层问题 |
| `signature/*` | 函数签名变了 |

## 全项目审视

审视基线为 `71f6608`，并在 `23bb0bc` 上复核（2026-11-04）。本文记录候选工作和验收方法，已确定的产品契约以 [设计说明](spec.md) 为准。P1 指可能造成工作丢失、错误结果或阻塞诊断的问题，P2 指可恢复的误操作、信息缺口或需先验证的成本。下列“验收”是未来验证步骤；本轮为代码和文档静态核查，未运行浏览器、故障注入或负载实验。

### API、文件与交付

- **P1 · 大流程包应在读入时限流（实现缺口）。** 导入接口先无上限 `await file.read()`，再把整个字节串交给有 200 MiB 上限的解析器。超限文件会在拒绝前占用应用内存。建议按块计数，超过上限立即返回 413，保留已有的解压大小限制。验收：在请求不声明长度时上传超限文件，仍提前拒绝且不创建流程；限内合法包正常导入。[导入入口](../backend/app/api/flows.py#L451) · [解析器限额](../backend/app/services/packages.py#L39)
- **P2 · 导入结果列出缺失附件（体验建议）。** 包内找不到引用的文件时服务端只记警告并保留哈希；若目标库也无此文件，接手者可能到执行时才发现资料打不开。建议区分“目标库已有”和“两边都缺”，在导入结果中列出需补齐的节点和文件。验收：同一份缺附件的包分别导入已有、没有对应文件的库，只有后者显示缺件清单。[缺件处理](../backend/app/api/flows.py#L489)
- **P2 · 删除业务工程前列清引用范围（需产品决策）。** 删除接口直接移除登记行，而运行时按工程标识查询当前登记。新启动的诊断可能因此失去已发布步骤使用的工程。建议先展示受影响的流程版本，再决定禁止删除被引用工程，还是改用停用和迁移。验收：同一工程分别被草稿、发布版本引用以及无引用时，操作者能在最终确认前区分影响并按选定策略处理。[删除](../backend/app/api/projects.py#L94) · [运行时查询](../backend/app/services/scheduler.py#L864)

### 调度、业务调用与恢复

- **P1 · 文件字段默认值应走同一条存储校验路径（实现缺口）。** 当人工采集字段有包含 `hash/path` 的默认值、请求又省略该字段时，调度器不会解析该引用。worker 随后填入默认值，只检查哈希类型。若业务函数按其中的路径读文件，可能访问服务账号可读的上传目录外文件。建议在统一补齐默认值后用平台存储解析路径。验收：哈希有效但路径伪造时只允许平台解析出的路径；哈希失效时在业务函数调用前拒绝，合法已上传文件仍可用。[调度器](../backend/app/services/scheduler.py#L656) · [worker 校验](../backend/app/worker/node_sdk.py#L69)
- **P1 · 超时应覆盖向业务进程发送请求（实现缺口）。** worker 在读请求前加载业务模块。若初始化卡住、大请求填满管道，调度器可阻塞在 write/flush，响应超时计时尚未开始。建议为发送和接收共用截止时间。验收：用阻塞初始化与超管道容量的负载触发，确认限定时间内结束或重试，进程回收、实例留下明确失败原因。[发送与计时](../backend/app/services/sessions.py#L95) · [业务模块启动](../backend/app/worker/session.py#L45)
- **P1 · 调度器不可用时别让诊断显示“运行中”（实现缺口）。** 调度模块导入失败会切换到空实现，启动方法直接返回，而启动接口已写入实例。建议拒绝启动或将本次实例明确置为失败。验收：模拟依赖导入失败，用户收到可操作的错误，不产生无人推进的 running 记录。[降级实现](../backend/app/api/instances.py#L32) · [启动调用](../backend/app/api/instances.py#L250)
- **P1 · 重启后区分中断与人工等待（需产品决策）。** 启动时初始化数据库，正在执行的调度线程却随旧进程消失。建议先识别中断并解释，再决定哪些动作允许人工重试；不要默认重新调用可能有外部副作用的业务代码。验收：分别在调用中、等待人工时重启，核对状态、历史、可用操作与执行次数。[应用启动](../backend/app/main.py#L36) · [既有待决事项](spec.md#11-尚未决定)

### 从发布版本到执行记录

- **P1 · 启动按钮应与已加载的发布版本表单绑定（实现缺口）。** 表单请求失败时页面仍展示“没有声明启动参数”和 JSON 输入，并允许提交；从版本 A 快速切到 B 时，迟到的 A 响应也可能替换 B 的表单。建议按发布 ID 接收响应，加载失败提供重试，只有成功确认无参数才显示自由输入。验收：延迟 A 或令 B 返回 500，不能对 B 提交 A 的参数，B 加载成功后可启动。[版本切换](../src/views/FlowReleases.vue#L88) · [启动按钮](../src/views/FlowReleases.vue#L286)
- **P1 · 实时更新中断时标明待办可能已过期（体验建议）。** 事件流会退避重连，但详情页没有连接状态；另一窗口完成任务后，断线页仍可能显示原待办。建议标示最后同步时间，在恢复连接时同步整份详情。验收：只阻断事件流，在另一窗口完成待办；旧页可辨认数据已过期，恢复网络后无需手工刷新。[重连逻辑](../src/services/sse.ts#L38) · [详情操作](../src/views/InstanceDetail.vue#L219)
- **P2 · 区分详情加载失败与实例不存在（实现缺口）。** 初次加载遇到网络或服务器错误时也显示“实例不存在或已被删除”，刷新入口依赖已取得详情。建议仅对 404 显示不存在，暂时性故障提供原地重试并重建订阅。验收：500 后恢复，无需离开页面即可查看详情并继续接收更新。[加载](../src/views/InstanceDetail.vue#L156) · [空态](../src/views/InstanceDetail.vue#L313)
- **P2 · 工程抽屉只接收当前工程的接口清单（实现缺口）。** 关闭 A 后打开 B，迟到的 A 响应可能显示在 B 的标题下；读取失败也落入与零接口相同的空态。建议校验请求归属，分别展示错误重试和真实空态。验收：A 慢于 B 时始终显示 B 的清单，B 加载失败时可直接重试。[接口抽屉](../src/views/Projects.vue#L174)
- **P2 · 从某流程进入历史时保留筛选（体验建议）。** A 的启动页跳转通用历史列表，没有传入 A 的标识。建议将流程 ID 放在可清除的查询条件中。验收：从 A 点“历史执行”及刷新均只看 A，清除筛选后可看全部。[跳转](../src/views/InstanceRun.vue#L102) · [列表筛选](../src/views/InstanceList.vue#L41)
