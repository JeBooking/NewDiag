# 固定值输入修复记录

固定值编辑器原先只监听 `change`，没有处理 Element Plus 输入框的 `update:modelValue`。输入文本未写回受控值，被旧值覆盖。对旧组件运行回归脚本，输入 `12` 后仍为 `null`，断言失败；修复后同一检查通过。

修复共用的 CompositionArgumentEditor：即时保存输入草稿，仅合法 JSON 更新业务配置，未完成 JSON 保留在输入框并显示“当前修改尚未保存”。外部值变化时同步草稿；节点参数按节点 ID 和参数名区分编辑实例，避免切换节点沿用未完成草稿。节点、操作调用、固定资源调用及嵌套字段中的固定值共同使用此编辑器。

实际检查：

- `pnpm type-check` 通过。
- `node scripts/check-composition-literals.mjs` 通过。使用真实 Vue 组件和受控输入替身，覆盖数字、文本、布尔、null、数组、对象、不完整 JSON、外部更新、只读及嵌套字段；不是浏览器或 Element Plus 集成测试。
- 后端推送前回归：162 passed, 7 warnings，无失败；警告涉及测试依赖弃用及 Windows 子进程管道清理。
- 浏览器手工验收未完成：内置浏览器连接本地隔离验证页超时，本机浏览器操作因无法确认当前 URL 被工具停止。临时验证服务已停止，未修改用户平台中的流程数据。

后续浏览器验收步骤：打开可编辑流程，选择带参数的排查节点，取消现场填写，选择固定值；输入 `12`、`"文本"`、`[1,2]`，确认可持续编辑并保存；输入未完成的 `[1,`，确认文本保留且显示错误，不覆盖上次有效值。完成输入后保存并重新打开，核对值及类型。再核对切换节点、撤销和嵌套字段的输入。
